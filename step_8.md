# Исправление проблемы с подключением к базе данных.

Какая на текущий момент есть проблема с соединением к БД? Давайте рассмотрим порядок того, как у нас работает подключение к базе данных:

```rust
pub struct ContractsSqliteStorage {
    connection: Pool,
}
```

Это структура, которая представляет собой хранилище контрактов с подключением к базе данных `SQLite` через **пул** соединений.

Теперь посмотрим, как мы работаем с этим соединением (функции структуры):

```rust
async fn add(&self, contract: crate::entities::Contract) -> 
    Result<(), Box<dyn std::error::Error>> {
        
        const QUERY: &str = "
            INSERT INTO contracts (id, name, created_at)
            VALUES (?1, ?2, ?3)
        ";

        let mut parameters: Vec<Value> = Vec::with_capacity(3);
        parameters.push(contract.id.into());
        parameters.push(contract.customer_id.into());
        parameters.push(contract.created_at.to_string().into());

        self.connection.conn(move |connection| {
            let affected = connection.execute(QUERY, params_from_iter(parameters))?;
            Ok(affected)
        })
        .await?;

    Ok(())
}
```

Что тут происходит?

1. Определяем запрос.
2. Определяем параметры запроса и подготавливаем их для выполнения.
3. **Просим новое соединение из пула и выполняем запрос с подготовленными параметрами.**
4. Возвращаем результат выполнения запроса.

В пунктах 3 и 4 мы используем **новое соединение из пула** для выполнения запроса.

Так же и работают другие методы, определенные в структуре `ContractsSqliteStorage`:

Берем новое соединение из пула и выполняем запрос с подготовленными параметрами, аналогично тому, как это делается в методе `add` и возвращаем соединение назад в пул.

## В чем проблема брать новое соединение из пула каждый раз?

Что такое **пул соединений?** Пул соединений - это набор открытых соединений к базе данных, который предоставляет их по мере необходимости (когда нужно выполнить взаимодействие с БД как в текущей реализации). 

Вместо того чтобы создавать новое соединение для каждого запроса, мы берем соединение из пула, используем его и возвращаем обратно в пул. Это позволяет переиспользовать ресурсы, что улучшает производительность при работе с базой данных.

Бизнес операция может затрагивать несколько запросов к базе данных, и если каждый раз брать новое соединение из пула, то возникает риск того, что эти запросы будут выполняться на разных соединениях. 

Это может привести к проблемам с согласованностью данных и транзакциями.

**Кратко говоря**: нам нужно, чтобы мы работали с конкретным выделенным соединением, для разных задач, во время одной бизнес-операции. Потому что это соединение может быть использовано для транзакции, которая может помочь в обеспечении согласованности данных и корректного выполнения всех запросов в рамках одной операции.

## Решение проблемы - свой управляемый пул:

Идея заключается в том, чтобы создать свой собственный пул соединений, который будет управлять выделением и возвратом соединений. Таким образом, мы можем гарантировать, что в рамках одной бизнес-операции будет использоваться одно и то же соединение.

В `contracts_impl` создадим файл: `managed_connection_pool.rs` и определим структуру со следующими полями:

```rust
type ManagedPool = (
    smol::channel::Sender<Client>,
    smol::channel::Receiver<Client>,
);

pub struct ManagedConnectionPool {
    database_path: String,
    max_connections_count: usize,
    pool: ManagedPool,
}
```

`database_path` - здесь, это просто путь к файлу базы данных `SQLite`. Он нужен будет, чтобы мы смогли создать перечень соединений. Раннее мы использовали его, чтобы создать пул соединений при помощи библиотеки `async_sqlite`.

`max_connections_count` - это максимальное количество соединений, которое может быть одновременно открыто в пуле. Оно определяет размер пула и ограничивает количество одновременных подключений к базе данных.

`pool` - это сам пул соединений, который управляет выделением и возвратом соединений. Он представлен в виде кортежа из отправителя и получателя канала `smol::channel`, через который происходит взаимодействие с соединениями.

```rust
type ManagedPool = (
    smol::channel::Sender<Client>,
    smol::channel::Receiver<Client>,
);
```

`type ManagedPool` - это просто алиас для кортежа. Изначально, тип данных следующий:

```rust
let (sender, receiver) = (smol::channel::Sender<Client>,smol::channel::Receiver<Client>);
```

`sender` - это отправитель канала, который используется для возвращения соединений обратно в пул после их использования.

`receiver` - это получатель канала, который используется для получения соединений из пула для выполнения операций с базой данных.

Комбинация `sender` и `receiver` образует управляемый пул соединений. `sender` используется для возврата соединений в пул после их использования, а `receiver` используется для получения соединений из пула для выполнения операций с базой данных.

## Реализация пула соединений:

Для того, чтобы создать пул соединений и сразу его наполнить нужен конструктор со следующей логикой:

```rust
pub async fn initialize(database_path: String, max_connections_count: usize) -> Self {
    let path_clone = database_path.clone();
    let (sender, receiver) = smol::channel::bounded::<Client>(max_connections_count);
    for _ in 0..max_connections_count {
        let connection = Self::create_connection(path_clone.clone()).await;
        sender.send(connection).await.expect("Не удается наполнить пул соединений.")
    }

    Self {
        database_path: path_clone,
        max_connections_count,
        pool: (sender, receiver),
    }
}
```

Объяснение:

Следующая строчка создает два канала: получатель и отправитель. Получатель используется для получения соединений из пула, а отправитель — для возврата/наполнения соединений обратно в пул.

```rust
let (sender, receiver) = smol::channel::bounded::<Client>(max_connections_count);
```

Следующая часть кода отвечает за наполнение пула соединениями по количеству `max_connections_count`.

```rust
for _ in 0..max_connections_count {
    let connection = Self::create_connection(path_clone.clone()).await;
    sender.send(connection).await.expect("Не удается наполнить пул соединений.")
}
```

Сама функция `create_connection` отвечает за создание нового соединения с базой данных. 
Здесь используется библиотечный `ClientBuilder` для создания нового **точечного** соединения, вместо пула.

```rust
async fn create_connection(database_path: String) -> Client {
    let builder: ClientBuilder = ClientBuilder::new().path(database_path.clone());
    builder.open().await.expect("Не удается открыть соединение.")
}
```

Это все основные шаги для создания инициализатора пула соединений.

---

Дальше нам потребуются функции для:

- Получение соединения из пула.

- Возврат соединения обратно в пул после использования.

Получение будет выглядеть следующим образом. Задействуется `receiver` канала для получения соединения из пула.

```rust
async fn acquire_connection(&self) -> 
    Result<Client, Box<dyn std::error::Error>> {
        let connection = self.pool.1.recv().await?;
        Ok(connection)
}
```

Следующая функция отвечает за возврат соединения обратно в пул после его использования. Задействуется `sender` канала для отправки соединения обратно в пул.

```rust
async fn return_connection(&self, connection: Client) ->
    Result<(), Box<dyn std::error::Error>> {
        self.pool.0.send(connection).await?;
        Ok(())
    }
```

Это все основные функции для работы с пулом соединений.

## Рефакторинг старых реализаций адаптеров работы с БД.

Возвращаемся к старым реализациям адаптеров работы с БД и будем их рефакторить с использованием нового пула соединений.

Сейчас следующая реализация использует пул соединений. При каждой операции с базой данных будет происходить получение соединения из пула и его возврат обратно после использования. Любой вызов: `get`, `add`, `remove`, `update` будет работать с новым соединением из пула.

```rust
pub struct ContractsSqliteStorage {
    connection: Pool,
}
```

Нам нужно использовать не `Pool`, а `Client` из нашего пула соединений:

```rust
pub struct ContractsSqliteStorage {
    connection: Client,
}
```

Остальной код менять не требуется. `Client` уже предоставляет функции `conn` для работы с соединением.
